# Translations (i18n)

Languages: English (source), Portuguese (Brazil) `pt-BR`, Spanish (Latin America) `es-419`,
Japanese `ja` (added 2026-09-30).
Planned later: French, Hindi, Arabic (right-to-left, needs layout work + fonts).

## How it works

- `src/i18n/` is a small in-house module, no library. Hermes has no
  `Intl.PluralRules` (i18next needs it) and there is no native module, so it
  ships over the air.
- `t('profile.settings.language', { name: 'x' })` returns a string. Keys are
  typed: a wrong key is a compile error.
- Placeholders are `{name}`. Numbers passed as params are formatted for the
  language (`1,234` / `1.234`).
- Plurals are `{ one: '…', other: '…' }` entries picked by `params.count`.
- `tRich(key, { name: <Text …/> })` puts React nodes (e.g. bold text) into a
  sentence.
- `formatNumber(n)` replaces `n.toLocaleString()`.
- The phone language is read from `Intl` (`pt-*` → pt-BR, `es-*` → es-419,
  anything else → English). The player can override it in Profile → Settings →
  Language (`chronos.language` in AsyncStorage).
- `LanguageProvider` wraps the navigator in `app/_layout.tsx`. `t()` reads a
  module-level language, so a change remounts the screens (keyed on the
  language) instead of relying on memoised strings recomputing. A language
  change therefore drops the player back on the home tab.
- **Never call `t()` at module scope** (constants evaluated at import). It
  runs before the language is known. Make it a function (see
  `src/config/store.ts`).
- Tests run in English: `jest-setup.ts` pins `deviceLanguage()` to `en`.
- `src/i18n/translate.test.tsx` checks every language has exactly the English
  keys and the same `{placeholders}`.

## Adding strings

1. Add the English text to `src/i18n/locales/en/<area>.ts` (register a new
   area in `en/index.ts`).
2. Add the same keys to `pt-BR/<area>.ts` and `es-419/<area>.ts`, typed with
   `satisfies Translation['<area>']`, and register them in each `index.ts`.
3. Replace the literal with `t('<area>.<key>')`.

Tone: informal "você" (pt-BR), informal "tú" (es-419), short and warm like the English.

Japanese glossary: Daily = デイリー, streak = 連続記録 (chip: {count}日連続), hearts = ハート,
coins = コイン, Campaign = キャンペーン, era = 時代, Museum = 博物館, artefact = 収蔵品,
leaderboard = ランキング, timeline = 年表, guess = 回答/予想する, Stage = ステージ,
Premium = プレミアム, Minerva = ミネルヴァ. Japanese has no plural: `one` and `other` are
the same text. BCE is `common.bce = '紀元前%y'`: `formatYear` puts the number where
`%y` is when the era word comes first (紀元前450). Store names stay in Latin script
("{store}で"). Large quantities use 万/億 in content; years are always digits.

## Status (2026-09-30)

UI strings: DONE for every screen (~650 keys per language across areas
common, tabs, store, profile, home, reminders, round, onboarding, paywall,
campaign, modes, social, account, achievements). Years use `displayYear()`
(JS thread) or `formatYear(year, t('common.bce'))` read in render for worklets.

Deliberately still English: brand names (Date Guesser, Premium, Google Play,
Play Games, App Store), dev-only buttons, server-sent social error messages,
and everything that comes from `src/data` (question text, category, topic,
region and campaign-route names). That last group is the content phase.

Known small gaps:
- A few numbers are passed as plain strings to keep English byte-identical
  (e.g. "N years away" on the reveal), so they get no thousands separator.
- Founder-note speech bubble lines are longer in pt/es; check wrapping on a device.
- Notifications use the language active when they were scheduled.

Next steps:
1. Device check in pt-BR and es-419 (layout overflow on HUD, chips, buttons, paywall).
2. Native-speaker review of the pt/es wording (shortest labels first: era chips, hints).
Content: DONE (2026-09-30; Japanese the same day). All 538 questions (title + reveal description),
12 categories, 23 topics, 6 regions and 10 campaign routes in pt-BR, es-419 and ja.
- Files: `src/data/i18n/<lang>/questions-1..6.json` + `meta.json`, merged in
  `src/data/i18n/index.ts`. Only fields players see are translated
  (`shortDescription`, `subtitle`, `country` aren't shown and stay English).
- `src/data/index.ts` getters return a translated view (same rows, same order,
  so seeded Daily/topic picks are identical across languages); English
  returns the original objects. Firestore and the seed script stay English.
- Anything without a translation (a new question, or one only in Firestore)
  falls back to English. `src/data/i18n/contentI18n.test.ts` fails if a bundled
  question/category/topic/region/route has no translation, so adding a
  question means adding its pt-BR + es-419 text too.
- Region/route names: `localizeRegion(region)` / `routeName(route)` from `@/data`.
- `scripts/exportContentStrings.ts` dumps the English source text as JSON for
  translating new content.
- Needs native-speaker review (proper-name choices were logged by the
  translators: e.g. Isabel I vs Elizabeth I, Tamerlão, Gengis Kan).

Language choice: phone language by default; switchable any time in Profile →
Settings → Language, and from a 🌐 pill on the first onboarding screen.

Outside the code: Play listing + screenshots per language, Play Games
achievement names, RevenueCat/Play product descriptions.
